# Read workflow

Use this workflow for vault-grounded questions and for any task that needs note context before acting.

## Build a read plan first
Before reading notes beyond a quick directory listing, create a Read Plan.

- Search first using listing, globbing, or grep-like discovery.
- Choose the smallest useful set of notes, usually 3 to 10.
- For each planned note, include:
  - path
  - why it matters
  - what you expect to learn
- Include a stopping rule such as:
  - stop after 6 notes if the answer is consistent
  - extend by 1 to 5 notes if contradictions appear

## Read incrementally
- Read notes in relevance order.
- Expand only when the first pass is insufficient.
- Prefer metadata, headings, backlinks, and short excerpts before loading full note content.
- Only load full notes for the top candidates or when exact wording matters.

## Answer from notes read
- Ground the answer in the notes you actually read.
- Prefer paraphrase over long quotation.
- Mention the note titles or paths relied on.
- Do not answer from memory when the answer depends on the vault.

## Clarifying questions
Ask one bundled clarifying question only when ambiguity would otherwise cause:
- mistaken project or area routing
- mistaken speaker or person identity
- wrong task ownership
- wrong note merge or link target
